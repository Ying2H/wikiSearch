# Wikidot 搜索系统设计

## 目标

为公开 Wikidot 站点提供独立的静态搜索页。服务器负责发现页面变化、读取内容、构建索引和发布；访问者在浏览器中加载静态资源并完成搜索。

系统优先保证：

- 抓取任务可恢复，失败不会推进错误的版本水位；
- 同一份一致性快照同时生成索引和显示页面；
- 动态页面在页面自身版本不变时仍能按 TTL 刷新；
- 构建失败不破坏上一份可用发布；
- 公开索引不被误认为权限系统。

## 系统结构

```text
ListPages / HTML 清单
        ↓
SQLite 页面版本、任务和依赖关系
        ↓
渲染 HTML + FTML 源码缓存
        ↓
一致性快照
        ↓
Orama JSON 索引 + 静态搜索页面
        ↓
gh-pages 分支 / GitHub Pages
```

Python 负责 HTTP、DOM 解析和 SQLite 状态；Node.js 负责 Orama 索引与浏览器脚本构建。所有网络请求经过统一的计数、限速、超时和错误分类层。

## 页面清单

系统支持两类清单来源：

- `html_manifest`：读取站点中的辅助清单页面；
- `amc_manifest`：直接读取 Wikidot AMC 的 ListPages 模块。

两类 provider 对上层提供相同的页面行数据：`fullname`、`title`、`updated_at`、`revisions`、分页游标和来源信息。

清单解析规则：

- 按 DOM 结构读取字段，不按竖线或固定行格式拆分；
- 标题可以为空、包含 Unicode、标点或 HTML 实体；
- 使用时间元素的机器可读 Unix 时间；
- 使用页面实际提供的分页链接，不猜测分页 URL；
- 清单页、导航、搜索页和其他排除页面不进入搜索语料；
- 清单内容经过 HTML 实体转义时只解码一次；
- 单轮分页具有预算，预算耗尽时不推进完整覆盖水位。

## 身份和版本

页面最终以 `(site_id, page_id)` 作为身份。没有取得内部 ID 时，使用 `fullname` 作为临时键，取得 ID 后再迁移到最终身份。

系统分别保存：

- `observed_version`：清单观察到的远端版本；
- `fetched_version`：HTML 成功抓取并校验后的版本；
- `source_version`：FTML 源码成功读取后的版本；
- `normalized_record_hash`：规范化索引记录的哈希。

三类版本不能互相替代，也不能通过对 `revisions` 或页面页脚版本号加减一推断另一类版本。

页面改名会迁移规范 URL、依赖边和任务键，并从索引中移除旧 URL。相同页面名但内部 ID 不同，视为不同页面。

## 增量扫描

清单扫描使用上一轮完整覆盖的远端时间作为水位，并保留重叠窗口：

1. 读取清单第一页，比较页面版本并合并变更任务；
2. 从带重叠的水位继续读取后续页面；
3. 对相同时间戳的所有页面全部处理；
4. 扫描结束后复读清单前沿，检查并发编辑；
5. 只有完整覆盖、前沿复查和任务入队事务成功时才推进水位。

时间排序清单不是事务快照。重叠扫描、前沿复查和低频完整清单核对共同降低并发编辑、分页插入和停机期间更新造成的遗漏风险。

普通页面版本变化时通常读取渲染 HTML 和 FTML 源码。动态页面 TTL 到期时读取 HTML；如果页面版本未变，可以复用已缓存的 FTML，发现新版本迹象后再重新读取源码。

## 内容读取和动态分类

FTML 用于识别动态模块和依赖关系，渲染 HTML 用于搜索正文。同步器不把模块语法直接当作搜索正文，也不执行页面脚本。

页面分类：

| 类别 | 判据 | 刷新策略 |
| --- | --- | --- |
| `static` | 源码已取得且没有动态特征或未解析依赖 | 页面版本变化触发，配合滚动抽检 |
| `dynamic-listpages` | 直接包含 `ListPages` | 独立 TTL |
| `dynamic-transitive` | include 或模板间接引入动态内容 | TTL，并接受依赖变化触发 |
| `dynamic-other` | 评论、评分、随机、日期或其他外部数据影响内容 | 独立 TTL |
| `unknown` | 源码失败、未知指令、参数化 include 或模板无法解析 | 保守 TTL，不归为静态 |

依赖关系记录同站字面量 include 的有向边，并维护反向依赖。被包含页面变化时，依赖页面进入 dirty 队列。循环、失效目标、参数化 include 和超出深度/节点预算的关系采用保守分类。

纯 CSS 模板若只影响外观可以不触发正文刷新；包含文本或动态模块的模板必须保留依赖影响。

## 刷新和请求预算

默认刷新策略：

- 清单 timer 每 10 分钟运行一次；
- 直接 ListPages 页面 TTL 为 1800 秒；
- 间接动态页面 TTL 为 1800 秒；
- 其他动态页面 TTL 为 3600 秒；
- 无法分类页面 TTL 为 3600 秒；
- 单站请求间隔至少 2 秒。

清单频率由 systemd timer 控制，页面 TTL 由 service 环境变量控制。修改方法见 [运行与定时任务说明](OPERATIONS.md)。

请求预算应分别统计清单、变化页面、动态 TTL、完整核对、重试和身份读取请求。达到预算时记录延迟并保留待处理任务，不能把未完成的 TTL 刷新标记为成功。

## 快照和 Orama 索引

只有 active 页面、版本一致、缓存文件存在且内容哈希校验通过的记录可以进入一致性快照。空正文、软 404、权限异常和未校验页面进入排除或隔离状态，不进入公开索引。

Orama 文档包含：

```text
id、title、fullname、category、page_type、content、url
```

构建端和浏览器端使用同一 Mandarin tokenizer，并统一大小写。搜索策略为：

- 标题和页面名权重高于正文；
- 多词查询使用分词搜索和 BM25 排序；
- 连续短语命中优先；
- 单个汉字只搜索标题和页面名；
- 不生成纯逐字符倒排索引；
- 页面脚本对索引加载失败、版本不匹配和旧资源提供明确处理。

索引、浏览器脚本和入口文件作为一个静态版本发布。构建输入、schema、tokenizer 和前端源文件发生变化时必须重新生成索引。

## 发布和回滚

构建器先写入暂存目录，成功后通过目录切换替换输出。装配器将入口、Orama 资源和 `build.json` 组成完整站点目录。发布脚本把站点目录提交到 `gh-pages`。

发布签名包含：

- 快照 `manifest_hash`；
- 入口文件哈希；
- builder、tokenizer、浏览器脚本和 Node 锁定清单哈希。

签名不变时跳过构建和推送。构建失败时保留上一份静态目录。删除页面通过新的全量快照生效，不能在旧索引目录中直接覆盖单个文件。

## 删除和权限安全

最近更新清单中缺少页面不能证明页面已删除。删除流程需要完整清单核对、有效不存在证据和二次确认。超时、5xx、解析失败、登录页或权限页不能作为删除证据。

搜索页和索引只适用于公开语料。将来若接入私有站点，入口、索引、静态资源和发布流程必须由同一认证边界保护。

## 数据模型

SQLite 中的主要实体包括：

- `pages`：页面身份、规范 URL、观察/抓取/源码版本和状态；
- `content`：HTML、FTML、标准化记录和提取器版本；
- `classification`：动态类别、分类原因和 TTL 时间；
- `dependencies`：页面间 include/template 依赖；
- `jobs`：合并后的任务原因、目标版本、重试次数和租约；
- `scans`：清单水位、重叠窗口、分页覆盖状态；
- `builds`：快照、索引和发布的构建记录。

所有任务入队和清单观察在同一事务中提交，worker 使用租约避免崩溃后任务永久丢失。

## 验证重点

部署或策略调整后应验证：

- 同秒多页面更新和分页期间插入更新；
- 停机期间超过第一页容量的页面更新；
- 中间分页失败不推进水位；
- HTML 与 FTML 来自不同版本时不生成一致快照；
- include 多层、循环、参数化和未解析目标；
- 动态 TTL 到期只产生一次任务；
- 内容删除后旧词从新索引消失；
- 构建失败保留旧版本；
- 结果链接跳出 iframe；
- 手机输入、中文分词和索引加载；
- 发布目录、GitHub Pages 和 systemd 状态一致。
